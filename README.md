# swift-github

Use this package when your code talks to the GitHub API and you want each capability as a value you can inject and replace in tests, without this package choosing HTTP, authentication or storage for you. Start from the client for the resource you need, such as `GitHub.Repository.Traffic.Client<Failure>`, `GitHub.Repository.Get.Client<Failure>` or `GitHub.Organization.Repositories.Client`. You supply the closures that make the calls. To mint a GitHub App installation token from a command line tool, start from `GitHub.App`. If you only need the request and response types, use swift-github-standard.

## Laws

- One-call clients do nothing but call your closure, so they throw your `Failure` unchanged.
- `GitHub.Organization.Repositories.Client.all(_:limit:duplicate:order:)`, `GitHub.Repository.Stargazers.Client.all(_:limit:)` and `GitHub.User.Repositories.Client.all(_:limit:)` follow each page's `next` until it is nil. They never return a partial list. Needing more pages than the page limit, collecting more items than the item limit, or reaching a request already made fails the whole traversal.
- A traversal checks for cancellation before and after each page fetch, and fails with `cancelled` when it finds it.
- In an organization traversal, the item limit counts repositories after the duplicate policy is applied. `first` keeps the first occurrence of a repository ID. `last` keeps the position of the first occurrence and the value of the last. `reject` fails on the second occurrence. `preserve` keeps every occurrence. The order is applied once, to the complete list, and `GitHub.Organization.Repositories.Traversal.Order.server` keeps the order the pages gave.
- `GitHub.App.resolve(identity:keyPath:name:)` takes the signing key from the `keyPath` argument, then the file `GITHUB_APP_PRIVATE_KEY_PATH` names, then the macOS login keychain item whose service is `name`. It takes the identity from the argument, then `GITHUB_APP_ID`, then that keychain item's account, which it consults only when the key also comes from the keychain. The identity must be all digits. The token cache lives in `~/.config/` under `name`.
- The keychain is read through `/usr/bin/security`. Off macOS, a key that would come from the keychain fails and names `GITHUB_APP_PRIVATE_KEY_PATH`.
- `GitHub.App.token(organization:permissions:now:)` accepts only a GitHub login as the organization: 1 to 39 ASCII letters, digits and hyphens, not starting or ending with a hyphen. A permission argument is `name=level`, each made of lowercase ASCII letters and underscores.
- A cached token is returned only while more than `GitHub.App.Token.refreshMargin` seconds (5 minutes) remain before it expires, and the result says whether it came from the cache. A missing, unreadable or corrupt cache entry counts as a miss. Each organization and permission set has its own entry, and the order of the permissions doesn't matter.
- On a miss the token is minted through the `gh` command line tool, found on the search path through `/usr/bin/env`, with the app's assertion as `GH_TOKEN` and `GITHUB_TOKEN` removed from its environment. The assertion is an RS256 JWT issued 60 seconds in the past and valid for 9 minutes.
- The token's expiry must have exactly the form `2026-08-01T12:00:00Z`, in UTC with no offset or fraction. Any other form fails the call.
- A minted token is written to the cache atomically, with the directory limited to the owner (0700) and the file to owner read and write (0600). If any of these steps fails, the call throws and the minted token is not returned.
